## Vision

### One-line positioning
**Civica is the AI compliance layer for SNAP enrollment — the caseworker before the caseworker. Same submission destination, less uncertainty.**

The applicant uses Civica's mobile app for intake. Our engine runs a dry-run that simulates the row-level determination the county worker will make. If the packet clears our dry-run, it clears theirs. CBOs license our dashboard + engine — keeping their existing submission workflow (BenefitsCal via Civica's Playwright using CBO Assister credentials) — but their packets are pre-verified before submission. Civica's recertification companion + ABAWD work-log retention + appeals generator handle the post-submission lifecycle that GetCalFresh exits.

### 10x Check / Cathedral Vision
- **Engine as moat:** measured per-CBO PER calibrated against USDA QC microdata, county-level PRA returns (CDSS Filings #1+#2 due July-Aug 2026), and Civica's own served-cohort outcomes — refreshed quarterly. No incumbent has this data stack.
- **Dry-run as guarantee:** "If packet passes our dry-run, your application clears the county worker's review." Not a money-back SLA (perverse incentives), not an outcome guarantee (county worker decides) — a **process guarantee** backed by a row-level shadow caseworker simulation.
- **Lifecycle ownership:** Civica is the only platform that stays from intake through recert through appeals. GetCalFresh exits at submission; BenefitsCal exits at determination; Propel arrives post-approval anonymous. Civica owns the relationship across all four stages.
- **Path-1-as-proof-of-concept:** Civica operates as its own CBO, generates measured cohort PER, and sells the same engine + dashboard to other CBOs as "we run on this, here are our numbers."

### Platonic Ideal — 12 months out
Civica is the default compliance + lifecycle layer adopted by 10-20 mid-size multi-program CBOs across CA, generating $200K-$500K SaaS ARR + measured cohort PER data sufficient to walk into CDSS in late 2026/early 2027 with "Civica-served cohort runs at 4.5-5.5% PER vs CA baseline 10.98%" as the B2G procurement case.

## Accepted Scope (added to this plan)

- **CBO-buyer-facing dashboard view** — `/cbo-preview` role exists; extend to show per-CBO PER vs CA baseline, per-element breakdown ("your org runs hot on shelter"), grant-reportable FNS-380-style export. Est: 2-4wk.
- **Engine integration pipeline for inbound PRA data** — ETL for CDSS Filing #2 returns (per-county PER + denial codes, due July-Aug 2026). Per-county calibration. Est: 2-4wk.

## Major risks
1. **Dry-run capability is the load-bearing claim AND the biggest build.** Without row-level narrative determination, "caseworker before the caseworker" is marketing, not capability. 2-3mo critical path.
2. **Per-CBO engine actionability is chicken-and-egg.** Civica-as-CBO Path 1 generates data only for Civica's own cohort. To make engine actionable per-CBO, need at least one paying CBO running through it for 6 months.
3. **Cabinet relationship ethics constraints** gate equity issuance + B2G timing. Sequencing B2G to 2027 helps but doesn't eliminate.
4. **GetCalFresh layer positioning requires integration discipline.** If Civica iOS app and GetCalFresh form fields drift, navigators re-key — friction kills layered pitch.
5. **CalSAWS API push has uncertain outcome.** 12-24mo BD with no guarantee. Playwright ops must be sized to assume API doesn't land.
