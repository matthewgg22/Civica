# CEO Plan: RegOps Engine — Automated Regulatory-Change Detection + Drafting

Generated by /plan-ceo-review on 2026-05-27
Branch: codex/rebuild-feb18 | Mode: SELECTIVE EXPANSION
Repo: matthewgg22/civica

## Premise (sharpened)

The user's framing — "automated, self-learning, self-correcting compliance engine" — is
the wrong frame and possibly dangerous. Legal text is not a domain where ML auto-adapts
without liability consequences. Sharpened framing:

**RegOps Engine** — a regulatory-change *detection* + LLM-assisted *drafting* pipeline
with a counsel-and-engineer review queue, ERE-falsification gate, and feature-flagged
rollout. Humans merge every mutation. No autonomous adaptation. Position internally
only — never marketed as "automated compliance."

**Approach A (the safe-landing fallback if drafting quality misses the bar at week 4):**
detection-only. Poll the same sources, diff into structured GitHub issues, post to a
dedicated label, no LLM drafting, no counsel queue, no war-room mode. The fy-rules-
refresh-checklist still owns the human handoff. ≤1 week to ship from scratch; drop-in
substitute if RegOps Engine v1 has to be cut.

The real moat is not a feature; it's **operational latency** at scale. At 2 states the
engine is overkill vs. the existing fy-rules-refresh-checklist + manual OBBBA audit.
At 5+ states it is load-bearing. Building it now is a forward investment justified by
the MA-first caseworker mode plan (Project Bread) already on the roadmap.

## Vision

### 10x Check (what would make this 10x more valuable)

A regulatory event happens in any of ~15 jurisdictions; within 72 hours the engine has:
detected it, drafted a PR against the rule corpus and copy registry, routed it to the
right counsel reviewer (state vs. federal vs. FTC), run ERE falsification against the
held-out eligibility dataset, posted a triaged update to the team's regulatory inbox,
and surfaced the user-facing banner if applicable. The team's compliance workload
becomes a queue, not a fire drill. State #6 costs the same engineering effort as state
#3 (≈ near-zero per state).

### Platonic Ideal

A boring tool. Internal-only. Lawyers see a queue with diff-renderers and
citation links. Engineers see auto-drafted PRs that mostly merge cleanly. The
Error Rate Engine becomes the falsification layer for engine-drafted changes —
exactly what it was built for. Marketing never mentions the engine exists.
The product feels timeless because the rules underneath are always current.

**Total v1 effort (honest, solo engineer, no parallelism):** ~11-13 weeks human-time
across all accepted scope (eval 2 + polling 2 + drafter/queue 3 + ERE/war-room 2 + FTC
2 + obs 2). With CC+gstack compression, realistic calendar time is ~5-7 weeks of focused
work assuming no major counsel delays. The earlier "6-8 weeks" estimate was sequencing
math without counsel-loop latency or eval-harness labeling. Counsel turnaround is the
historical bottleneck (see OBBBA audit Track 2 — items pending since 2026-05-12);
the engine cannot move faster than counsel is willing to.

**Distribution opportunity cost:** Significant. This work delays SEIU/UFW/gig channel
investment by ~1 quarter. The decision to ship this now is a bet that operational
latency at state #3+ matters more than additional household acquisition in CA-only.
This bet should be revisited at the 4-week mark — if distribution channels are slipping
or counsel is non-responsive, cut scope back toward **Approach A** (detection-only:
poll sources, post structured GitHub issues, no LLM drafting, no counsel queue, no
war-room mode — see Premise section for full Approach A definition). Approach A is a
≤1-week ship and a safe landing pad.

## Architectural Decisions (from review)

**From CEO review (2026-05-27):**

- **Runtime:** GitHub Actions (poll) + Cloudflare Workers (counsel API) + Vercel/Next.js
  (counsel queue UI). Matches existing enrollment-api + dashboard stack.
- **Prompt-injection mitigation:** Structured-extraction prompts only (JSON-schema-locked
  output). Source text never concatenated into instruction position. 15-20 adversarial
  fixtures in the LLM test suite — locked down before week 3.
- **Data model:** Policy timeline with supersession edges (`supersedes: PolicyId | null`
  on each PolicySnapshot). Graph-walk query computes "what's active today." Handles CA
  CDSS ACL chain natively.
- **Bus-factor mitigation:** Ruthless runbook discipline. Every source adapter,
  war-room trigger config, counsel routing rule, and ERE gate threshold documented.
  Standard: a contractor could ship a fix in <1 day. Adds ~3-4 days to v1.

**From eng review (2026-05-27, this revision):**

- **LLM drafter runtime — Cloudflare Workflows (not raw Workers).** Workers' 30s CPU
  limit collides with 20-60s legal-extraction LLM calls. Workflows is the platform's
  step-based pattern that resumes across CPU windows and persists across retries.
  Adds ~1 day to v1; keeps drafter on the CF stack.
- **Source-of-truth coupling — snap-rules authoritative for runtime; engine timeline
  is staging.** iOS keeps reading `packages/snap-rules/data/*.json` like today. The
  engine's policy timeline is visible to counsel + dashboard via a "pending supersession"
  banner. PR-merge is the commit point. No iOS-side runtime dependency on the engine.
- **Citation provenance — append-only audit log, separate from working snapshot store.**
  Every `SourceAdapter.fetch()` call writes (source, url, hash, ts, response headers,
  body-ref) to a Supabase `regops_audit_log` table (or R2 if cheaper). Immutable.
  Liability Posture #2 ("chain of custody") relies on this, not on git history.
- **Counsel queue auth — thin 'counsel reviewer' role + magic-link + domain RLS.**
  New Supabase role distinct from staff/buddy/applicant. RLS policies scope queue
  access by domain (CA/MA/Federal/FTC). Magic-link signin for external lawyers.
  ~3 days; critical path to T11 (counsel staffing must complete before week 3).
- **SourceAdapter return type — typed discriminated union.**
  `FetchResult = Success<RawDoc[]> | NoChange | TransientFailure | StructuralFailure | SourceWedged`.
  TS compiler enforces handling at every consumer. Refactor cost at state #5+ avoided.
- **LLM prompts — versioned templates directory.** `packages/regops-engine/src/prompts/{name}.v{N}.md`.
  Drafter loads by name+version. CI checksum gate ties eval baselines to prompt versions
  so quality regressions are attributable. ~0.5 day v1 cost.
- **Adversarial prompt-injection fixture suite — required CI gate from v1.** 15-20
  fixtures (Anthropic public corpus + SNAP-specific legal-text-shaped injections).
  Failing the suite blocks any drafter PR from merging. Security control made visible
  and enforced.
- **ERE held-out dataset coverage — meta-test asserts 100% rule-path coverage.**
  2k evals must exercise every rule path in `FederalDefaultRules.swift` + `ca.json` +
  `ma.json`. Auto-fail on coverage drop. Closes the "gate passes vacuously on rare
  paths" hole.
- **SourceAdapter base class bakes in polling hygiene.** Hourly cap per source,
  exponential backoff on 429/5xx, identifying User-Agent (Civica + contact email),
  robots.txt respect. Per-adapter override allowed. ~2h v1; avoids government-site
  IP-block risk during August COLA window.

## Accepted Scope (v1)

- **Source-pluggable polling layer** with launch configs for: USDA FNS COLA + SNAP
  policy memos, federalregister.gov SNAP/FNS-tagged docs, CA CDSS ACL feed, MA DTA
  Helpful Charts, FTC press releases + enforcement actions.
- **Snapshot + diff store** in a dedicated package (`packages/regops-engine` proposed).
  Each source has versioned snapshots; new pulls produce structured diffs.
- **LLM-assisted draft generator** that produces PRs against `packages/snap-rules/src/data/*.json`,
  `Civica/Features/SNAP/Rules/FederalDefaultRules.swift`, the snap-compliance-copy
  registry, and (for FTC) marketing/app store copy. Every draft includes extracted
  citations, side-by-side diff, and a confidence score.
- **Counsel queue UI** routed by domain (state ACL → state policy counsel; federal →
  federal policy counsel; FTC → marketing counsel). Reuses existing string-signoff
  workflow patterns. Audit trail in repo.
- **ERE falsification gate** — any draft touching eligibility math must pass regression
  against a held-out eligibility dataset before merge eligibility. (See Section 6 for
  the eval harness investment this requires.)
- **War-room mode** triggered by bill page-count threshold + SNAP keyword density +
  citation-impact heuristic. On trigger: fan-out to counsel queue, post dashboard
  banner, run ERE re-validation across the full rule corpus, schedule 30-day retro.
- **Feature-flagged rollout** — every engine-drafted change behind a flag with
  `effectiveOn`/`expiresOn`. Existing stale-rules banner consumes these dates.
- **Internal-only positioning** — no marketing surface, no product page, no app
  copy mentioning the engine. It is ops infrastructure.

## Open Questions (resolved before implementation, not during)

- **LLM extraction quality bar — labeling owner.** Founder is not a SNAP attorney; he
  cannot self-grade a precision bar on legal text. Two acceptable resolutions:
  (a) hire/retain counsel for 20 hours to label the eval set (~$5k one-time) and treat
  ≥90% precision as the hard gate, OR (b) downgrade to a founder-labeled "obvious-error
  smoke test" and explicitly accept that the bar is weaker than counsel-grade. Pick
  one before week 1 starts. **Default if undecided at week 1:** option (b), and the
  engine ships with a "engineer-validated, not counsel-validated drafts" disclaimer
  on the counsel queue.
- **Counsel sign-off — named reviewer per domain.** OBBBA audit shows counsel
  turnaround is the existing bottleneck (Track 2 items pending since 2026-05-12).
  Engine cannot move faster than counsel will. Before week 3, name a counsel reviewer
  for each domain: state policy (CA + MA), federal SNAP policy, FTC marketing. If no
  reviewer exists, the queue stalls and the engine is shelf-ware. Acceptable SLAs
  *once counsel is staffed*: federal/state 5 biz days, FTC 10 biz days, war-room 24
  hours. **Until counsel is named, the engine produces drafts but does not auto-route
  — drafts park in a holding queue with no SLA promise.**
- **ERE falsification gate — mechanics.** ERE v0.2.0 just shipped (PR #199/#273);
  the held-out dataset must be defined. Proposal: 2,000 historical eligibility
  evaluations spanning all rule paths, refreshed quarterly. Pass threshold: ≥99.5%
  match on the held-out set against pre-change baseline. Owner: same engineer who
  owns ERE. Any change failing the gate cannot be merged.
- **Source adapter contract.** Each source implements `SourceAdapter` with:
  `pollFrequency`, `fetch() → RawDoc[]`, `diff(prev, curr) → StructuredDiff`,
  `domainTag` (eligibility | copy | ftc), `authConfig?`, `rateLimitConfig?`,
  `retryPolicy`. State #6+ "near-zero cost" claim holds only if the adapter contract
  is real. Sketch the TypeScript interface before week 2 starts; check it against
  CA, USDA, federalregister, MA before committing.
- **Source-down behavior.** USDA FNS site down for a week during COLA season:
  source-health monitoring + Sentry alert + on-call escalation. Polling continues with
  backoff. No fallback data fabrication — silence is the correct answer.
- **War-room trigger calibration — N=1 problem.** Only one historical event (OBBBA).
  The trigger heuristic (page-count >100 + SNAP-keyword frequency >20 + CRS "major
  legislation") is a tripwire, not a tuned model. First 3 trigger fires require manual
  review before fan-out is automated; if 2 of the first 3 are false positives, the
  trigger is retuned, not the model retrained. Until manual review of 3 fires, war-room
  mode notifies but does not auto-fan-out.
- **FTC pipeline scope — pick a side.** D3 was accepted (over CEO recommendation),
  AND the prior open-question text said "cut FTC first if over 8 weeks." Internal
  contradiction. **Resolution: FTC stays in v1 scope, but with reduced fidelity —
  detect FTC actions and route to manual counsel review only, no LLM drafting against
  marketing copy in v1.** Saves ~1 week vs. full FTC drafting pipeline. Full FTC
  drafting is deferred to a follow-up sprint.

## Liability Posture (load-bearing — read before building)

1. **No autonomous mutation.** Every engine-drafted change requires human merge.
   Counsel sign-off for any change affecting eligibility math, exemption criteria,
   or user-facing legal copy. Engineering sign-off for any change affecting product
   surfaces.
2. **Citation provenance.** Every draft links to source document + extracted passage +
   timestamp + URL hash. If a regulator audits, the chain of custody is in git.
3. **ERE falsification gate.** No eligibility-affecting change ships without passing
   ERE regression. The held-out eligibility dataset is the regression's ground truth.
4. **Internal-only positioning.** Marketing site and app copy never mention the engine.
   "Automated compliance" claims invert the liability asymmetry the OBBBA Q19 row-16
   incident exposed.
5. **Feature flags everywhere.** Every engine-drafted change ships behind a flag with
   `effectiveOn`/`expiresOn`. Stale-rules banner consumes these. Rollback = flag off.
6. **Annual external counsel audit** of the engine's behavior — does it match what
   actually happened in the regulatory landscape? First audit 12 months post-ship.

## Implementation Sequencing (recommendation, not commitment)

Week 1-2: Eval harness for LLM extraction. Hand-label dataset. Build precision/recall
infra. No engine code until quality bar is real.

Week 2-3: Source-pluggable polling layer + snapshot store. Wire CA CDSS + USDA FNS +
federalregister.gov first. Output: structured diffs to a queue, not yet drafts.

Week 3-5: LLM draft generator + counsel queue UI. Wire snap-rules + snap-compliance-copy
as draft targets. Add MA DTA source.

Week 5-6: ERE falsification gate integration. War-room mode trigger + fan-out.

Week 6-7: FTC sub-pipeline (detection + counsel-routing only in v1; no LLM drafting
against marketing copy until follow-up sprint per Open Question §FTC).

Week 7-8: Observability + on-call runbook + retrospective infrastructure.

**Gate check at week 4:** If drafting quality is below precision target, stop and
re-scope toward Approach A (detection-only). Don't ship a bad drafter.

## How this CEO plan differs from a typical greenfield plan

The compliance domain has unusual liability asymmetry. Most product mistakes are
recoverable; a regulatory error documented in court filings is not. This plan is more
conservative than the user's original framing intentionally — what looks like rigor is
actually liability risk management. The strategic upside ("self-learning engine"
narrative) was traded for downside protection ("internal-only, human-in-loop,
ERE-gated"). If the user wants to maximize narrative, this is the wrong design. If
the user wants to maximize the probability that Civica can defend its compliance
posture in front of a state auditor 18 months from now, this is the right design.
